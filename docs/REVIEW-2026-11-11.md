# CursorBeacon 第二轮全量检查（2026-11-11）

范围：`src/` 全部模块、配置默认值、启动/恢复路径、光标渲染与替换、Raw Input/轮询、全屏判定、打包与部署。
方法：逐文件源码审查、Clang 静态分析、编译验证、运行日志/实测轨迹复核。

## 结论

在源码层面发现并修复了 **5 个明确的逻辑/可靠性问题**，其中 2 个会直接导致用户可见故障。仍有一个**参数调优限制**和若干已知功能缺口；本机还叠加了 Device Guard 部署限制。

没有发现新的内存破坏、越界、注入或提权问题。

## 已修复（源码）

| # | 严重度 | 问题 | 修复 |
|---|---|---|---|
| 1 | 严重 | `now_us()` 用 `QPC计数 × 1,000,000` 直接做 64 位乘法；10MHz QPC 下系统 uptime 超过约 10.67 天后溢出为负数，检测器/状态机全部时间判断失效。重启进程无效，只有重启系统能重置 QPC | 改为 `qpc_to_us()` 整数分解：`秒×1e6 + 余数×1e6/freq`，并增加 11 天 uptime 的回归测试 |
| 2 | 高 | 默认 `cursor_set` 只有 Arrow/IBeam/Hand/Crosshair。分屏边界和窗口边缘使用 `SizeWE`/`SizeNS` 等调整光标，检测虽然触发，但当前光标形状不在替换列表里，用户看不到放大 | 默认改为 `all`；本机配置也改为 `all`，启动日志显示 `cursors=14` |
| 3 | 高 | `SystemParametersInfo(SPI_SETCURSORS, ..., SPIF_SENDCHANGE)` 会同步广播 `WM_SETTINGCHANGE`；任意顶层窗口无响应时，恢复调用可能永久阻塞控制器 | 恢复改为 `SPI_SETCURSORS` + flags `0`，不广播；系统光标仍会重新加载 |
| 4 | 中 | 渲染器在某个倍率下产出空帧时，控制器只禁用 effects，没有恢复上一次已放大的系统光标，可能留下大号光标 | 空帧时先 `effector.restore()`，再禁用 effects |
| 5 | 中 | Raw Input 在锁屏/桌面切换/设备变化后可能停止；`SetTimer` 失败也未检查，watchdog 不会运行 | 增加 5 秒健康定时器，重新 `RegisterRawInputDevices` 并重设 watchdog；`SetTimer` 失败时降级到轮询 |
| 6 | 低 | `ShakeDetector::decay()` 用 `last_processed_us_ == 0` 判断初始化，首样本时间戳为 0 时衰减不生效（纯逻辑/测试场景） | 改用 `has_last_sample_` |
| 7 | 低 | `PointerSource::start()` 在旧线程仍 joinable 时重新赋值 `std::thread` 会 `std::terminate` | 启动前 join 旧线程 |

## 校验结果

- `cmake --build`：通过，无编译警告。
- Clang Static Analyzer（`clang++ --analyze`）：对核心/平台/控制器 12 个 TU 扫描，**无 analyzer 警告**。
- clang-tidy：本机 Device Guard 现在拦截 `clang-tidy.exe`（Permission denied），无法运行；此前版本无 analyzer 级问题。
- 单元测试/独立测试 exe：Device Guard 拦截，无法在本机执行；修复版自测也无法运行。仅能确认编译与静态分析。
- 运行中的旧版 0.1.0（已重启系统、QPC 归零）：
  - 3Hz、±300px 合成晃动触发 4x，并自动逐级恢复。
  - 分屏测试期间日志出现大量 `scale` 事件，证明检测成功；看不到放大是光标形状覆盖问题，已用 `cursor_set=all` 解决。
  - 当前服务 PID 4872，配置 `sensitivity=8`、`cursor_set=all`、`max_scale=4`。

## 仍未解决/需验证

1. **慢速晃动的阈值限制（中）**
   - 旧版参数：600ms 窗口、3 次反转、净位移/幅度 ≤0.35。
   - 约 2Hz 的自然晃动可能因净位移/幅度比例被拒；3Hz 可触发。灵敏度只能调整反转数/速度/幅度，不能改窗口和比例。
   - 建议下一版改为 800ms 窗口、净位移/幅度 ≤0.6，并用 2Hz/2.5Hz/3Hz 轨迹做回归；这需要新二进制部署后验证。

2. **修复版无法在本机部署（部署阻塞，不是代码 bug）**
   - 修复版 exe（当前源码构建，未部署）SHA256：`0D32BFBA508FBD8381596AA96915CA23628FD25FC524BDFBBF8121DCE48FD404`
   - Device Guard 按哈希拦截；需要 IT 放行或可信签名。
   - 当前本机仍运行旧版 0.1.0；重启后约 10.6 天内可用，之后 QPC 会再次溢出。

3. **SPI 恢复不再广播的回归风险（需实测）**
   - 改为 flags 0 后系统光标应正常恢复，但个别应用可能需要 `WM_SETTINGCHANGE` 才刷新图标缓存。部署修复版后需验证资源管理器、浏览器、终端等窗口。
   - 如果出现恢复不彻底，可改为在独立低优先级线程里做一次 `SendNotifyMessage(HWND_BROADCAST, WM_SETTINGCHANGE, ...)`，避免阻塞控制器。

4. **Raw Input 健康重注册的开销/行为（需浸泡）**
   - 每 5 秒重注册一次，通常无副作用；需要 8 小时运行、锁屏/解锁、睡眠唤醒、USB 鼠标重插测试。

5. **自定义光标**
   - `SetSystemCursor` 只能替换标准系统光标。分屏中若某个应用自绘光标，仍不会放大；需要 overlay 兜底或应用白名单。

6. **全屏检测仍只覆盖前台窗口**
   - 后台全屏窗口、z 序扫描未实现；独占全屏游戏需要逐项实测。

7. **其他已知限制**
   - `.ani` 放大期间可能首帧；光标主题变更需重启；混合 DPI 仅 144 DPI 三屏实测；`sampling_mode` 配置字段目前是保留字段；未签名 exe 可能触发 SmartScreen/AV。

## 建议优先级

1. 让 IT 放行修复版哈希或签名，部署后验证 SPI 恢复、Raw Input 重注册、全部分屏光标形状。
2. 下一版调整慢速晃动窗口/净位移比例，并补 2Hz 轨迹测试。
3. 增加自定义光标 overlay 兜底（可选）。
4. 给 CI 增加 `workflow` scope 后推送 Actions，恢复独立的 27 项 doctest。
